    Верификация 0.4.0a3 на Linux+CUDA (T4, Python 3.13) — GREEN

    • pytest 72/72 (оба блокера ночной сессии закрыты: acquisition без округлений, publish_gate с самодостаточным YAML);
    • attach → write → nll на cuda; очистка Δ возвращает выходы бит-в-бит (max_diff 0.0, deterministic-режим CUDA + CUBLAS_WORKSPACE_CONFIG).

    TPU-чип

    • Kaggle TPU-VM: XLA BPTT-цепочка работает на чипе (S3 OK, сессия отменена на 2ч);
    • Colab (v5e, Python 3.13, torch 2.14.1): чип виден через JAX 0.11.2; torch_xla из PyPI не совпал по ABI с предустановленным torch (_XLAC.so: undefined symbol) — в ноутбуке есть ячейка установки совпадающей пары + restart;
    • S3b (JAX-путь, без torch_xla) — ВЫПОЛНЕНО НА ЧИПЕ (владелец, 05.11): устройство TPU_0, математика D1 (read T⁰+Δ → writer → D1-write) 8.4 мс/итерация (max 0.156с — JIT-компиляция первой итерации), loss конечен на 20 итерациях; отчёт: kaggle-evidence/colab-tpu/results/S3b_accel_jax.json;
    • BPTT-обучение на чипе — XLA-путь после restart'а пары (ячейка xla_install в ноутбуке).

    vLLM (Linux GPU, Kaggle T4)

    • Экспорт артефактов на Linux GPU — OK: export_for_vllm → ngram_table_merged.npz + vllm_config.json (sha256, provenance) — путь 1 работает на целевой платформе;
    • Движок vLLM — OK: установка через uv-venv (обход конфликта vllm↔предустановленный torch Кагла), facebook/opt-125m запущен и сгенерировал текст на T4 (21.4 tok/s output); артефакты AtomicNG присутствуют в том же окружении;
    • Хук merged-таблицы в граф движка — Track B/upstream (docs/vllm.md, путь 3);
    • Урок для пользователей: на образах с предустановленным torch ставьте vllm через uv-venv (пример — kaggle-night-vllm/verify_vllm3.py).

    Известные ограничения

    • Бит-точность отката на CUDA требует deterministic-режима (на CPU бит-точность без флагов);
    • XLA: хэш биграмм остаётся на CPU (grad-stop интерфейс), тензоры на чипе;
    • vLLM-ридер — v0.4+/Linux (не калибровался).
