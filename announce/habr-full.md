## ВАРИАНТ Б — вступление без личной ноты

**AtomicNG** — фреймворк для forward-only записи новых знаний в n-gram память LLM. Реализация метода из статьи Hao Wu ([arXiv:2610.31125](https://arxiv.org/abs/2610.31125)): предобученная хэш-таблица `T⁰` заморожена, новые знания накапливаются в разреженном патче `Δ`, и очистка патча возвращает исходную модель **побитово**. Apache-2.0, `pip install atomicng`, ядро — чистый NumPy.

---

## Проблема

Новые знания в LLM обычно добавляют двумя путями, и оба тяжёлые:

- **Файнтюн** — меняет веса: дорого, требует GPU-часов, и при неудачном смешении данных модель «забывает» старое (catastrophic forgetting);
- **RAG** — знания лежат снаружи в базе: модель их не «знает», это поиск по документам с подстановкой контекста.

Статья Hao Wu предлагает третий путь: у ряда современных моделей (Qwen3.8-Flash-Next, DeepSeek-класс) есть **встроенная n-gram sidecar-таблица**, которую модель читает на равне с весами. Именно эту таблицу можно дописывать: веса заморожены (`T⁰`), новые знания копятся в разреженном патче `Δ`:

```
T = T⁰ + Δ
```

Запись — только forward-проходы: маленький writer (~4M параметров) превращает текст в цели для строк таблицы, а правило D1 (block averaging) вливает их в патч. Ключевое свойство: **очистка `Δ` возвращает исходную модель побитово** — удаление знаний структурное, а не «разучивающее».

## Правило записи D1

Для блока событий, бьющих в строку j:

```
A_j = (1/n) · Σ βₐ·vₐ       — усреднённые цели
w_j = (1/n) · Σ βₐ          — средний гейт
Δ_j⁺ = (1 − w_j)·Δ_j + A_j  — выпуклая комбинация
c_j⁺ = c_j + 1              — счётчик блоков
```

Выпуклая комбинация означает: нормы патча ограничены (Proposition 1 статьи) — тысячи записей не взрывают таблицу. Гейты βₐ выдаёт writer (σ(B_θ[x, Δ, v−Δ, log(1+c)])) — модель сама решает, насколько сильно доверять новой записи.

## Фреймворк AtomicNG

Ядро — чистый NumPy (без ML-фреймворков), torch — опциональный слой. 85 тестов, включая **conformance-набор**: реализация побитово сверяется с формулами статьи (специальный golden-тест замораживает публичный API).

```python
import atomicng

model = atomicng.TinyModel()
atomicng.write(model, "Новый факт про кенгуру.")
atomicng.verify_deletion(model)   # очистка Δ ⇒ побитовый откат — гарантировано
```

[КАДР: quickstart.png]

Что внутри:

- **Writer'ы plain/delta** (MLP по статье) и BPTT-тренер сквозь цепочку записей D1;
- **Нативный read-out** (Track B): 16 голов × d=160 → 2560 → value + gated key пути → 10240;
- **vLLM-мост**: entry-point `vllm.general_plugins` + `atomicng export-vllm`;
- **Write-safety**: бюджеты строк и норм проверяются ДО изменения патча (атомарно), audit-лог append-only, точный undo через pre-image журнал, подпись артефактов Ed25519;
- **Протоколы оценки статьи**: acquisition Δ_empty/Δ_donor, distraction retention@k, chain drift — бенчмарки с регрессионными гейтами в CI.

## Честные ограничения

Прогон **обученного чекпоинта** (860 шагов, SmolLM2-135M) по протоколу из комментариев к моему анонсу:

- Acquisition на самом документе: ≈ 0 (max +0.0033) — это sanity check, не доказательство обобщения;
- **Парафразы документа: −0.09 … −2.05** — записи сейчас ухудшают парафразы (коллизии хэшей: дельты строк срабатывают в чужом контексте). Это доминирующий эффект на моём масштабе обучения; в статье writer обучается на 100M токенов, что этот эффект решает;
- Несвязанный текст: ровно 0.0 — идеальная локальность.

Плюс: undo точен только в LIFO-порядке (последний блок); vLLM-хук в граф движка — upstream-работа (сегодня — merged-table экспорт).
